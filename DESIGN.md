# bctx Agent Architecture - Design Document

**Version**: 2.0
**Date**: 2026-05-16
**Status**: Design Phase

---

## Executive Summary

**bctx** is being redesigned as a complete agent harness system that replicates the Jarvis-like autonomous agent architecture from the work laptop. It will transform Claude Code agents into self-learning, grounded, competent assistants that operate autonomously while continuously improving through observation, reflection, and memory.

### Core Vision

> **Turn any Claude Code installation into a Jarvis-like system** where agents have:
> - **Memory**: Persistent context across sessions
> - **Observation**: Monitor all actions and detect patterns
> - **Reflection**: Learn from experience and improve
> - **Verification**: Ground actions in reality, prevent hallucination
> - **Coordination**: Multiple agents working together intelligently

### Key Principles

1. **Exact Replica**: Mirror the work laptop's agent architecture
2. **Easy Installation**: `bctx install` sets up everything
3. **Non-Invasive**: Works within `.claude/` ecosystem
4. **Additive**: Preserve existing bctx utilities, enhance them
5. **Production-Ready**: Reliable, observable, debuggable

### 3. Memory System

#### Three-Tier Memory Architecture

**Short-Term Memory (STM)**
- **Scope**: Current session only
- **Storage**: In-memory (managed by bctx during session)
- **Content**: Files read, commands executed, observations, working context
- **Lifetime**: Cleared on session end
- **Purpose**: Avoid redundant operations, maintain coherence

**Long-Term Memory (LTM)**
- **Scope**: Persistent across all sessions
- **Storage**: `~/.claude/memory/bay/`
- **Content**: Patterns, workflows, anti-patterns, reflections, user preferences
- **Lifetime**: Permanent (pruned by relevance over time)
- **Purpose**: Continuous learning, knowledge accumulation

**Episodic Memory**
- **Scope**: Historical record
- **Storage**: `~/.claude/observations/` and `~/.claude/sessions/`
- **Content**: Complete observation logs, session transcripts
- **Lifetime**: Archived monthly
- **Purpose**: Pattern mining, audit trail, deep learning

**Agent Discovery Flow**:
1. Agent receives task
2. Reads `~/.claude/CLAUDE.md` (navigator)
3. Sees: "Check `~/.claude/memory/bay/` for agent patterns"
4. Reads `~/.claude/memory/bay/index.yaml` (lightweight metadata)
5. Scans entry summaries, identifies relevant ones
6. Loads specific entries (e.g., `entries/observer-pattern-002.yaml`)
7. Applies learned patterns to current task

### 5. Hook System

**Hook Lifecycle Points**:

| Hook | When | Purpose |
|------|------|---------|
| `pre_session` | Before Claude Code session starts | Load context, prepare environment |
| `post_command` | After each user command | Update observations, check for reflection triggers |
| `pre_tool_call` | Before any tool invocation | Verify parameters, check prerequisites, anti-pattern detection |
| `post_tool_call` | After tool execution | Log outcome, update observations, check success |
| `on_error` | When errors occur | Log error, attempt recovery, trigger error reflection |

**Hook Implementation** (Example: `~/.claude/hooks/pre_tool_call`):

```bash
#!/bin/bash
# bctx pre_tool_call hook
# Installed by: bctx install

# Call bctx binary to handle observation
bctx observe --event pre_tool_call --data "$@"

# Exit code: 0 = allow, non-zero = block
exit $?
```

**Pattern Detection**:

```python
class PatternDetector:
    """Detects patterns in observation streams"""

    def detect(self, observations: List[Observation]) -> List[Pattern]:
        patterns = []

        # Sequential patterns: "Read often followed by Edit"
        seq_patterns = self.detect_sequences(observations)
        patterns.extend(seq_patterns)

        # Frequency patterns: "Bash called 80% of time for git ops"
        freq_patterns = self.detect_frequencies(observations)
        patterns.extend(freq_patterns)

        # Anti-patterns: "Edit without Read fails 82% of time"
        anti_patterns = self.detect_failures(observations)
        patterns.extend(anti_patterns)

        return patterns
```

```python
class ReflectionEngine:
    """Analyzes observations and generates learnings"""

    def reflect(self, trigger: ReflectionTrigger) -> Reflection:
        # 1. Collect relevant observations
        observations = self.collect_observations(trigger)

        # 2. Analyze patterns
        success_patterns = self.analyze_successes(observations)
        failure_patterns = self.analyze_failures(observations)

        # 3. Generate insights
        insights = self.generate_insights(
            success_patterns,
            failure_patterns,
            trigger
        )

        # 4. Create learnings
        learnings = self.create_learnings(insights)

        # 5. Store in LTM
        self.store_to_memory(learnings)

        return Reflection(
            id=f"refl_{timestamp}",
            trigger=trigger,
            observations_analyzed=len(observations),
            insights=insights,
            learnings=learnings
        )
```

### 8. Verification System

**Pre-Action Verification Framework**:

```python
class VerificationFramework:
    """Multi-level verification before actions"""

    def verify_tool_call(self, tool: str, params: Dict) -> VerificationResult:
        checks = []

        # File operation checks
        if tool == "Edit":
            checks.append(self.verify_file_read_in_session(params["file_path"]))
            checks.append(self.verify_file_exists(params["file_path"]))

        # Bash command checks
        if tool == "Bash":
            checks.append(self.verify_no_unquoted_spaces(params["command"]))
            if "git push" in params["command"]:
                checks.append(self.verify_git_account())
            if "mkdir" in params["command"]:
                checks.append(self.verify_parent_directory(params["command"]))

        # Git operation checks
        if tool in ["Bash"] and any(git_op in params["command"]
                                     for git_op in ["git commit", "git push"]):
            checks.append(self.verify_git_status())
            checks.append(self.verify_no_secrets_staged())

        # Run all checks
        results = [check.run() for check in checks]

        # Aggregate
        if all(r.passed for r in results):
            return VerificationResult(allowed=True)

        # Block or warn
        blocking = [r for r in results if not r.passed and r.severity == "block"]
        if blocking:
            return VerificationResult(
                allowed=False,
                reason=f"Blocked by: {[r.name for r in blocking]}"
            )

        return VerificationResult(allowed=True, warnings=[...])
```

## Data Flow

### Complete Agent Lifecycle with bctx

```
1. USER STARTS SESSION
   ↓
2. pre_session HOOK → bctx observe
   - Load LTM context from ~/.claude/memory/bay/
   - Read CLAUDE.md navigator
   - Initialize STM
   - Restore session state if resuming
   ↓
3. USER SENDS REQUEST
   ↓
4. AGENT PROCESSES
   - Check memory for similar tasks
   - Plan actions
   ↓
5. BEFORE EACH TOOL CALL
   pre_tool_call HOOK → bctx observe
   - Run verification checks
   - Detect anti-patterns
   - Block if needed, else allow
   ↓
6. TOOL EXECUTES
   ↓
7. AFTER TOOL CALL
   post_tool_call HOOK → bctx observe
   - Log observation
   - Update STM
   - Detect patterns
   - Check reflection triggers
   ↓
8. IF ERROR
   on_error HOOK → bctx observe
   - Log error context
   - Attempt recovery
   - Trigger error reflection if threshold reached
   ↓
9. AFTER COMMAND
   post_command HOOK → bctx observe
   - Update observations
   - Check for reflection triggers
   - Update context
   ↓
10. IF REFLECTION TRIGGERED
    bctx reflect
    - Analyze observations
    - Extract patterns
    - Generate insights
    - Store learnings to LTM
    ↓
11. SESSION ENDS
    - Store session log
    - Update LTM with session insights
    - Clear STM
```

## Appendix

### Glossary

- **STM**: Short-Term Memory (session-scoped)
- **LTM**: Long-Term Memory (persistent)
- **Observation**: Logged action with context
- **Reflection**: Analysis of observations to generate learnings
- **Pattern**: Recurring sequence or correlation in observations
- **Anti-pattern**: Known failure mode to avoid
- **Verification**: Pre-action checks to prevent errors
- **Hook**: Lifecycle event handler
